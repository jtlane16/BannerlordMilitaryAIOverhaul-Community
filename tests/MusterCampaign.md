# Campaign muster fixture

## Unattended acceptance (preferred)

1. After the coordinator confirms the acceptance build is installed and armed, start Bannerlord and load a **disposable copy** of a campaign save. A wartime save with intact kingdoms gives the runner a better chance of finding a viable matchup.
2. Leave the game on the world map and let time run. The runner starts fast-forward if the map starts paused and is safe. If the game opens a native menu or inquiry, return to the map when safe. No console commands or target choices are required.
3. Wait for **MAIO campaign acceptance**. Return the displayed result and run ID to the coordinator. `PASS` requires the original army to receive the nominated follow-on and physically join its native camp. `INCONCLUSIVE` means the save could not exercise the case within the limits, not that an issued order counted as a pass. Evidence is in the MAIO Desktop log.

The acceptance build claims the marker on campaign load. An unarmed load does nothing. To isolate reuse, the runner assembles at the **friendly frontier fort it will guard**, not at a separate fief. It requires physical presence and ready strength, issues a native guard for a full campaign hour, and then lets the standard handoff decide whether the same army can besiege the nominated neighbor. Manual Stage 2 marches still use a separate muster fort and the specified deadline.

The run is bounded to three actual attempts, 360 campaign hours, and 15 real minutes. Discovery favors nearby parties and checks land routes, native siege strength, priority, and influence before calling anyone. The admission budget is based on the remaining run time, with slow-movement headroom for gathering and the merged army's siege trip plus some time kept for a different candidate when tries remain. Quotes are not evidence of arrival. Protected cleanup can remain pending after the result. Any completion popup waits for the safe map UI. The runner does not create or overwrite saves.

For a movement interruption, look for `Muster visit recovery before/after` or `Muster visit before cancellation` (before disband changes native state). The commander checks the current fort, order and army objective, and uses the native movement-path builder in addition to the route-distance estimate. A cleared `Hold` may be reissued to the same destination at most twice per leg, at least one campaign hour apart. These limits survive reload. Six unprotected campaign hours without measurable route progress close the leg; protected events do not extend the assignment's original deadline. Recovery never forms a replacement army, repeats summons, or counts as arrival.

### Coordinator setup (not a tester step)

Build with `CampaignAcceptance=true`, run `tests/RunSmoke.ps1` with `-CampaignAcceptance`, then stage the verified DLL outside the installation. The coordinator-only `tests/InstallAcceptance.ps1` takes the staged `-Package` directory and the tested `-ExpectedHash`; it checks the game and launcher are closed, then replaces only the DLL and puts the marker beside the installed `SubModule.xml`. Include an `acceptance-reuse-v1.armed` file in that package with ASCII contents `reuse-v1 ` followed by a fresh 32-character GUID without hyphens. Do not reuse a run ID or overwrite a pending marker. Keep the `.claimed`, `.result`, and `.shown` receipts for reload deduplication. Ordinary builds omit the runner entirely. The same disposable save can be used with a new arm after its prior result was shown and its owned cleanup is safe and complete. A pending arm does not replace an unfinished run or bypass a protected cleanup.

## Manual diagnostics (optional)

This opt-in fixture uses real parties from **one** named kingdom. It does not start on load or on the daily force report. It marches on land to **one** friendly, unbesieged fortification, then releases the army. It is not siege relief and does not start a war. Use a disposable copy of an acceptance save.

1. Load the save, unpause briefly so takeover and `Force inventory` run, then pause on the world map. Open the Bannerlord console (`Alt`+`` ` `` on a US keyboard). The command is `maio.muster`.
2. For example, if Vlandia still owns unbesieged Pravend, enter `maio.muster preview vlandia town_V3 300 30`. Arguments are kingdom ID, target ID, required fighting strength, and campaign hours from the first tick that processes `start`. `preview` changes nothing. Read `BannerlordMilitaryAIOverhaul.log` on your Desktop for the actual participants, route, ETA, and costs. The 8-hour march is a unit-test input, **not** Pravend's actual route. The planner picks a separate friendly fortification for muster.
3. For a success run, use a preview that says `Feasible` **with at least one call**, then issue the same command with `start` instead of `preview`. If the example is infeasible or needs no calls in this save, choose a strength above the preview's leader power (derive it from committed power minus logged call power) that an eligible summons can meet, or increase the hours and preview again. Use the daily inventory to find alternative kingdom and fortification IDs. Close the console and unpause. `maio.muster status` shows the phase, exact target, required strength and absolute deadline. Expect `gathering` → `marching` → `finished` with `arrived-by-deadline`.
4. For a failed preflight, enter `maio.muster start vlandia town_V3 1000000000 30` (use the same usable kingdom/target IDs as above). Unpause. Expect `no-feasible-plan`, with no formation, orders or charge.
5. For an actual cancellation with traveling summons, reload the pre-start copy or choose another feasible plan whose summons has a nonzero route. Start it, advance just enough for `status` to show `gathering`, pause, enter `maio.muster cancel`, and unpause. Verify that the army and traveling summons release, each actual debit occurs once and is not refunded, and released parties return to vanilla. A native battle or siege defers release; if you manually join the test army, leave it manually before release can proceed.
6. For save/resume, save and reload once during `gathering`, once during `marching`, and once after `finished`. Verify `Muster loaded` and no repeated formation, call, debit, or release. Start another run only by issuing a new explicit `start`.

If an unneeded invitee is independently fighting at departure, look for `Muster surplus cancellation deferred` and a separate `Muster departure`. The ready army marches while the recruit remains in its battle. The original summons then releases once it is safe, including after reload. A battle involving the leader or an attached member still locks the formation.

Use the logged `Muster request`, `preflight`, `debit`, `summons`, `attachment`, `review`, `departure`, `arrival`, and `release` entries to reconcile the map and the paying leader clan's balance. Keep the map at low speed while stepping or cancelling. Native parties can move, fight, change strength, or become ineligible between preview and start; the start always preflights again.

## Sustaining and closing an assignment

Add **guard hours after arrival** to keep a real assignment active after the short march. The original march deadline applies only to the march. When the army arrives, it receives a native `DefendSettlement` order for the nominated friendly fort. Without a guard duration, the original commands still release on arrival. There is no live relief-target selection.

```text
maio.muster preview vlandia town_V3 300 48 1200
maio.muster start vlandia town_V3 300 48 1200
maio.muster status
```

Use a disposable campaign save and a feasible preview. For a **paid** boost, prefer a plan with several paid calls from other clans; a small or same-clan army can have a zero native upkeep price. `1200` hours is 50 campaign days: it is a test service window, not a deadline for live relief. Native cohesion normally decays only a few points per day, so let the guard run at map fast-forward and check `status` and `Upkeep` entries. If needed, choose a longer guard window at the start. Do not assume low cohesion will occur before a short march ends or that natural events will leave the army intact for 50 days.

- **Full/partial/unaffordable:** Pick a save and feasible leader clan whose *remaining* influence is comfortably above 200, modestly above 200, or at/below 200 respectively when cohesion crosses below 50. Compare `fullCost`, `nativeCost`, `actualDebit`, and cohesion before/after. Influence and costs can change during the guard; the 230/45 partial example is deterministic in smoke tests, not guaranteed live. For natural loss, let a nonzero-priced army go unboosted and observe `Assignment native dispersal` if it reaches the native threshold. No forced morale, influence, or cohesion setup is required or supplied. Save/reload while guarding and after a purchase; verify no duplicate payment.
- **Reuse:** Open `maio.muster neighbors town_V3` to list **native one-ring** IDs and owners. Pick a friendly origin with a weak neighboring fort held by an enemy **already at war**, and nominate that exact ID after the guard duration: `maio.muster start vlandia town_V3 300 24 1 <enemy-fort-id>` (adjust the march deadline to a feasible preview; do not type the angle brackets). At the handoff, verify `decision=reuse`, the same army ID, and `native=approaching` followed by a real camp if it reaches the target. Observe what Bannerlord actually does: an issued order alone is not siege or capture evidence. The assignment closes on capture, war ending, loss of camp without capture, loss of feasibility before camp, cancellation, or natural dispersal. No second offensive target is picked.
- **Reject and release:** Repeat with no nominated follow-on, a real fort not shown by `neighbors`, or an adjacent enemy fort that fails the native strength check. Observe the reason and release of the same formation. A reachable higher-priority home or formally allied defense vetoes the offensive handoff; this fixture does not assign relief in its place.
- **Cancel a follow-on:** Enter `maio.muster cancel` after the `native=camp:` entry but before an assault. Look for `Assignment withdrawal` and `Muster release`. If other AI parties are in the camp, verify that only the test army leaves and that the siege continues under the remaining participants. An active battle or player involvement defers withdrawal; save/reload while deferred and verify that it resumes only when safe, without upkeep or a reissued siege order.

The headless suite substitutes navigation, enemy strength/score, and pricing inputs where a campaign engine is needed. It runs the installed native boost, movement and release actions. Live battle, capture, and full save serialization still require campaign acceptance.
